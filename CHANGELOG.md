# Changelog

Draft-stage repo: versions move fast pre-1.0, and process docs may run ahead of the engine **only** when the debt is marked in the gate table and recorded as an open obligation in `docs/GAPS.md` (the layer-parity rule, v0.5.3). Run `./install.sh --check` in a consuming repo to see what an upgrade changes. Tags land only at doc/engine parity milestones. **The top entry of this file is the package version — the single authority (v0.5.5, pilot N2).** File headers carry the version of the commit that last modified them — checked against git history (`git log -1 -- <file>`), not merely against the entry list, or every stale stamp passes (pilot D2); `formats.json`'s stamp must equal the top entry. Both checks join the parity sweep (OBL-PKG-08).

## v0.6.2-draft — 2026-08-24
- **Pilot #1 (frisbii) feedback round** — 11 upstream files reviewed; 3 already answered (probe route v0.5.3, gate-6 vacuity v0.5.3, v0.5.2 parity v0.6.0), F-3 (install omits GATES-SPEC) confirmed fixed since v0.6.0, and the 7 live findings all adopted. PO decisions 2026-08-24: F-9 full (column + lint), F-11 full (step 0 + refusal + gate), HANDOFF limit stays advisory with the count fixed.
- **GATE-13 — plan Verify non-vacuity (F-9).** The pilot proved the class: a task's Verify is the sole mechanical arbiter of COMPLETED, GATE-4's scope predicate cannot see a markdown task row, and nine inert verifies shipped in one run (three past adversarial review). Adopted both halves as designed there: a mandatory `Non-vacuity` cell per task (names the wrong answer the Verify rejects; cites something runnable per GATE-4's rule; `MANUAL` exempts) plus a lint for five idioms that each shipped a real vacuous check, with a visible `lint-ok:` escape. Binds on unsigned plans only (frozen artifacts stay frozen); invoked at G2 with GATE-8, deliberately NOT in the sweep (a mid-P1 run without a PLAN.md is legitimate; at G2 it is not). The pilot's local id was GATE-12 — renumbered 13, 12 was already the obligation block.
- **GATE-3 verdict vocabulary (F-10).** P3 mandates verifier grades and GATE-3 rejected them (56 hits, 10 the mandated `PASS`). A Grade/Verdict column is now checked against `verdict_vocab` — PASS / PASS-with-carry-forwards (CV id in row) / FAIL (VF id in row) — because a status describes the work and a verdict judges it, and COMPLETED+FAIL is the run's most important pair.
- **Citation bodies admit one level of balanced braces** (frisbii braces finding): `awk '{…}'`, jq objects, `{7,40}` quantifiers are citable. An ev: opener the format still cannot parse is reported as *the format cannot express this* — never as the writer's citation being malformed for the wrong reason.
- **Dep probes are allowlisted before execution (S-2).** `probe:` ran under `shell=True` with nothing constraining it — the pilot's demonstration probe wrote a marker file and GATE-6 passed. The first word must now match `probe_allowed` (default: repo-local script; `probe_command_pattern` override in wow.config.json), checked BEFORE running, no calendar fallback. The test with teeth is theirs: the marker file must not exist.
- **Phantom runs refused (S-6).** Archiving strands empty run-id dirs (git tracks no empty directory); status derivation listed them as active for exactly the person who published. gate-7 refuses a run dir holding no files; status.mjs skips it. Predicate is files-on-disk, not git-tracked — deviating from the suggestion deliberately, so a brand-new run before its first commit stays real.
- **P5 step 0 owns the merge to main (F-11)**, and the destructive permissions regeneration (step 5) is guarded: gate-7 at `--p5` refuses a branch behind main (`main_candidates` / `main_branch` override) — the pilot showed a published grant that two blocked waves earned would have been silently dropped.
- **HANDOFF line count fixed** — the counter included the trailing newline, so "80" meant 79 and five consecutive commits trimmed a file that was already right. Counts as `wc -l` now; the limit itself stays advisory (PO 2026-08-24), stated in FORMATS §8.
