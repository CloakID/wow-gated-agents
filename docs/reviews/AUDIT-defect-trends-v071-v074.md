# AUDIT — defect trends & fix quality, v0.7.1-draft → v0.7.4-draft (monthly, OBL-PKG-22)

Scope: every change from the v0.7.1-draft close (7c4722a, 2026-09-13) through v0.7.4-draft (30aa7dc, tag `v0.7.4-draft`, 2026-09-22; HEAD of `main` at audit time, `main...origin/main` in sync per last fetch). Second audit in the loop CONTRIBUTING §Release quality defines; the previous one is [AUDIT-defect-trends-v060-v071.md](AUDIT-defect-trends-v060-v071.md). Method: git history + CHANGELOG per release, grep-verified code sites at HEAD, the five review reports of R9/R10/R11, registry state, and a full suite run at HEAD (`run-all.sh` → ALL GATE TESTS PASSED, 442 assertions across 16 files, 2026-10-06). Every claim is cited (file:line, grep count, git) or labeled INFERENCE. Run unattended by the PO's scheduled task on 2026-10-06; no pilot repo was reachable from this session (same limitation every release since v0.7.0 has recorded — §5.5).

**Verdict in one line:** no high-severity defect in the shipped version, but five of the six prior families recurred at a higher rate per release, a sixth family ("the fix fails inside its own defect class") is now the dominant pre-publish finding type, and the self-imposed class-question rule decayed within three releases — §6 lists eight defects in v0.7.4 itself, the worst a medium (AT-3 inflation through a fence kind the same release closed elsewhere).

## 3. Conceptual/structural challenges the trends point at

1. **Throughput is outrunning closure, and the backlog of class work is aging in lockstep.** 139 records in nine days, +46% engine, the reduction round deferred and its target grown by the amount it meant to save (§1). Every class-closure obligation that was open at the last audit is still open (OBL-PKG-17, -18, -19, -20, -24 — §3.3), and a defect-fix release was "inserted ahead of" the structural round by PO decision (CHANGELOG:6). The pilots are now current (v0.7.3+) and filing at a rate the instance loop absorbs in days; that is the success that creates this risk.
2. **A prose rule failed in the repo that exists because prose rules fail.** CONTRIBUTING rule 1 ("the class question is part of every fix … stated in the CHANGELOG entry") was adopted on 2026-09-13. Compliance by release, counting top-level CHANGELOG bullets carrying any of `class|instance|family`: **v0.7.2 7/11, v0.7.3 7/12, v0.7.4 3/11** — and v0.7.4's "Five high-severity engine defects" bullet (CHANGELOG:9) carries none of the three words for any of its five fixes. The R9/R11 remediation blocks (34 and 32 review-finding ids referenced) contain 'family' 4 and 0 times respectively. The rule was followed while fresh and decayed under volume within three releases — the framework's founding observation, reproduced on itself. The mechanical half (a sweep lint on CHANGELOG bullets that cite a finding id) was never registered.
3. **Round labels re-aged in four days.** The 2026-09-13 refresh (audit A5) set six successors to "engine round 7"; v0.7.2 WAS round 7 (OBL-PKG-20's own cell) and shipped 2026-09-17 discharging none of them. At HEAD, of **20 open rows**, **11 name a round at or before the current one**: OBL-PKG-04/05/09/12/15/17/20 (round 7 = v0.7.2), -18 (round 4), -19 (round 5), -24 (round 8 = v0.7.3, the release that discharged the round-8-labeled OBL-PKG-23), and -16 (successor "PO decision" but discharge text still says "engine round 3"). Six more say "v0.7.5 round" and are current. The parity check (OBL-PKG-21) reads version tokens; it was designed to leave round labels to this audit — so the structural fix is to stop using round labels as successors at all (§8-B6), not to refresh them monthly.
4. **Two engines, one rule, nine implementations.** status.mjs now ports gates.py helpers one at a time as reviews catch divergences (`cellsOf` ← `_cells` ADV-R9-02; `stripFencedBlocks` ← `_strip_fenced_blocks` ADV-R10-03). Each port is a new Family C site and a new Family F risk; the dialect-verdict corpus test that would catch meaning-level divergence (OBL-PKG-24) is itself an aged row. §6.1 is a port that was not made.
5. **Verification against real pilot artifacts has been zero for four consecutive releases** (CHANGELOG lines 6, 19, 49, 63 — the verification-honesty line every release carries, honestly). The pilot repos are directories on the same machine as the working clone (`~/Projects/cloakid-platform`, `~/Projects/cloakid-validation-prodsim`, `~/Projects/frisbii-subscriptions` — names-only listing). INFERENCE: this is a session-access habit, not a technical limit; a release session that connects two more folders can run gate-3/gate-7 over the real RUN-REPORTs the findings came from.

1. **The package's own intake rule was not enforced by the package.** v0.7.2: "intake is now coupled to upgrading — the pilots move to v0.7.2 and answer the standing upgrade-RCA question before the next feedback batch is triaged" (CHANGELOG:49). v0.7.3 triaged platform F-65…F-70 with "the upgrade-RCA question remains unanswered in both older pilots" (CHANGELOG:19); v0.7.4 triaged 23 more with "platform's upgrade-RCA answer is still owed formally, though F-76/F-77 are its upgrade findings in substance" (CHANGELOG:14). The coupling that mattered (upgrade before filing) held and closed the dead-code class (§7); the half that was the previous audit's A6 question (why pilots didn't upgrade) was waived twice in writing. Either collect the one answer or strike the rule — a rule stated and twice waived is the drift class the registry exists to prevent.
2. **The bash 3.2 fix was never executed under bash 3.2.** Stated honestly (CHANGELOG:6, "guarded structurally … because the suite runs under a newer shell here"), and then DEV-R11-16 found the guard itself checked the wrong version ("checks 3.2, not 3"). A dialect-portability fix verified by code reading only, in a family (F-35's sibling, CHANGELOG:8) whose lesson was that spelling-level reasoning about dialects fails. No macOS/bash-3.2 leg exists in the suite or the release checklist.
3. **Frisbii's version is stated twice, differently, uncited.** "Frisbii dormant at v0.5.0" (CHANGELOG:19, v0.7.3) and "Frisbii stays dormant at v0.5.1" (CHANGELOG:14, v0.7.4). No `ev:` on either; the pilot repo was not reached by either session. One is wrong; this audit could not determine which (frisbii-subscriptions not connected).
4. **OBL-PKG-05's engine half partly landed without touching the row.** F-76 (v0.7.3) made the G4 resolver skip a `status: blocked-draft` draft (gates.py:2738) — that is the convention OBL-PKG-05 says is "unenforced", and the row (docs/GAPS.md:11) does not mention the resolver reads it now. Meanwhile the vocabulary has no formats.json key (`grep -c blocked-draft formats.json` → 0), so the half that landed landed as an inline literal (§6.5).
5. **Nine vacuous tests were found and no class question asked.** v0.7.4: "nine survived a first run because their tests were vacuous … which is the proof working" (CHANGELOG:16). It is — for the nine tests that a fresh mutation happened to probe. Mutations are written per fix, so a pre-existing test is probed only when a new fix touches its path. INFERENCE: the suite's vacuity rate outside the current fix's blast radius is unmeasured; the GATE-13 non-vacuity rule the package imposes on consumers (two negative tests per gate) has no analogue "every test must be killed by some mutation" for the package's own suite. A one-off mutation sweep over the existing suite would settle it.

## 7. What held up well

- **Intake coupling closed the dead-code class.** v0.7.2 was "the THIRD consecutive dead-code round" (7 of 20 findings targeted already-fixed code, CHANGELOG:49); v0.7.3 received "the first fully-current batch ever received … zero triage waste" (CHANGELOG:19); v0.7.4's 23 were all "against live HEAD" (CHANGELOG:6). A policy decision, measured before and after, with the measurement in the record.
- **The fresh-context review loop is the structural answer to Family F, and it works.** Three review rounds, 76 findings, every blocking one remediated before publish, and a delta review that attacked the fixes themselves (ADV-R10) and found three had failed in-class — which is the only reason those three are not pilot findings. v0.7.3 was "the first release to ship only after two fresh-context reviews" (CHANGELOG:18).
- **Mutation discipline scaled**: 80 mutations in three releases, each "killed by exactly its own tests", nine vacuous tests exposed and replaced (CHANGELOG:16, :46).
- **Every previous-audit action landed or was registered** (A1–A3, A7 in 7c4722a; A4→OBL-PKG-20; A5→OBL-PKG-21 discharged; A6 mechanical half in status.mjs:566–567), and the verification-honesty line has appeared in all four releases since.
- **Spec-ahead-of-engine instances were registered, not deferred silently** (OBL-PKG-28/29/30), and `jira.status_conventions` closed an old one by becoming engine-read (F-73).
- **The suite is green at HEAD on a fresh VM** (Python 3.10, node 22, bash 5.1 — 442/442, 16.4s), and the formats.json API contract (`ids_expanded` with parity-on-drift, `schema_version`, `$removed`) is the first consumer-facing class closure for upgrade breakage (platform/F-76).
