# P4 — REPORT & RECONCILE — DRAFT v0.7.5
Entry: `/wow-report <run-id>` · Output: the reconciled SPEC (v<N+1> for `feature`; in place for `fix`/`audit`/`probe`/`remediation` — step 3) + `walk-G4.md` + classified next actions · Gate: **G4 (PO sign-off)** → Jira bugs/transitions.
Load: the RUN-REPORT's row counts and `## audit triggers` table (through status.mjs), the SPEC's headers and AC table, `docs/GAPS.md`; the walk preparer loads RUN-REPORT and `reports/*.md` whole (v0.7.5 R13b, DEV-R13-06 — the ORCH is a router, not a reader). (v0.6.3, F-11: `docs/TRACEABILITY.md` is dropped — no phase produced it, no gate read it, and a Load line pointing at nothing makes operators invent formats mid-gate. The traceability home IS the RUN-REPORT plus the run's `reports/`, which survive archival.)

## [ORCH] — prepare, then walk with PO
1. **GATE-10 divergence diff first** (`runs/<run-id>/divergence-G4.md`, checked with `scripts/wow/gates.sh gate-10 --run <run-id> --gate G4` — the gate-OPEN check; the walk artifact of step 2 is demanded at step 4's CLOSE form, never here — ADV-R11-04): compare git technical statuses / sign-offs vs Jira workflow per FORMATS §10 mapping; every out-of-mapping pair classified with the PO (git wrong / Jira wrong / **real gap** → actionable item in this walk). Ticket-side scope discussion lands in the spec (content home), cited.
2. Walk the run report **into `runs/<run-id>/walk-G4.md`** — one row per failed/blocked/parked/defect item with its classification: **fix iteration** (→ `/wow-plan` on `r<N+1>`) · **spec wrong** (→ `/wow-spec` revision) · **defer** (DEFERRED row, successor + discharge) · **accept as gap** (→ `docs/GAPS.md`, taxonomy-tagged) · **resolved-in-run** (v0.7.5, platform/F-98; a `## defects` row whose status is `OPEN` is a walk item too, DEV-R12-18: a plan defect repaired at G2a before execution, or any item closed inside the run — routes NOWHERE and therefore MUST cite the repairing commit or amendment in the walk row; `gate-2 --close` refuses it uncited. Before this class the only fit was "accept as gap", which pushed closed records into the registry F-51 keeps for open obligations). The walk's population is the RUN-REPORT's rows: a `DEF-plan-<nn>` is a walk item from the first cell of a FAILED/BLOCKED/PARKED row (a range `DEF-plan-01 … DEF-plan-05` enrols every id it covers), or from prose when no row anywhere carries it — never from a COMPLETED row's evidence cell. **Batch, don't raise** (v0.7.4, prodsim/F-86 — P4's 'Park, don't ask'): findings surfaced DURING the walk (a re-run check that does not reproduce, a bookkeeping discrepancy) are recorded as rows and disposed of together at G4, never raised to the PO serially as they are found — two items out of twenty once consumed a context window before the walk was enumerated, and the PO named it disproportionate. Re-running a check mid-walk stays encouraged; the routing half is what was missing. **The enumeration and the re-runs are delegated** (v0.7.5, FORMATS §14): a walk-preparer AGENT reads the RUN-REPORT and every report body and writes the walk rows with the classification cell EMPTY; mid-walk re-runs go to a delegate in batches, results by item id; the ORCH takes the hand-backs to the PO and fills the classifications with the PO — it reads no report body itself. **Walk row format** (FORMATS §4): `| <item id> | <classification> | <disposition> |` — the first cell is the RUN-REPORT row's first cell (the task id for a FAILED/BLOCKED/PARKED row, `DEF-plan-<nn>` for a defect), matched whole, so `T1` never stands in for `T10`. `gate-2 --close` (step 4) refuses while an item the RUN-REPORT carries is absent from the walk (`runs_layout.walk`), and its PASS states `walk: N/N`.
3. **Reconcile the spec — the home depends on the spec's `kind:` header** (P1 records it; `gap_row.spec_kinds`; a spec with no `kind:` reconciles as `feature`) (v0.7.4, platform/F-74: two consecutive runs overrode the mandatory v<N+1> by PO decision, and the second even when the contract materially changed — the amendment mechanism expressed it better than a version bump that re-points every `ev:file{…-vN.md}` citation in the registry). **`kind: feature` → a new version v<N+1>**: the contract is new work and a fresh document is its honest home. **`kind: fix` / `audit` / `probe` / `remediation` → reconcile IN PLACE by default**: append a `## Reconciliation — <run-id>` section and carry contract changes as `AM-<nn>` blocks (F-29's machinery); mint a new version only when the PO decides the contract changed enough to warrant re-pointing references, and record that decision in the section. Either way **the choice is recorded**, so a reconciliation in place reads as a decision, not a phase half-done. Then: every `DEV-U<n>-<nn>` is individually ratified into the reconciled spec (referenced by its stable ID) or declared a defect to revert. **`VF-U<n>-<nn>` findings are reconciled the same way** (v0.7.3, platform/F-67): a verifier finding that changed a contract, a command, or a prohibition lands in v<N+1>'s reconciliation section by its stable id — and (v0.7.5, platform/F-104) every VF and CV that names a check or a command the spec's ACs keep is lifted into the section by id, whether or not it changed a contract, so the next planner loads it from the spec AND from the prior run's reports (P2 Load line) — the signed spec is what P2 loads, so this is the ONLY door through which a run's hardest-won knowledge reaches the next planner. The one measured miss shipped the same credential-disclosure defect twice, a month apart, from the same corrective intent, past the reviewer who proposed it. The spec never silently diverges from the code.
4. Update single homes: REQUIREMENTS technical statuses for this run's REQ IDs, GAPS. Then close GATE-2 in its close form — `scripts/wow/gates.sh gate-2 --close --run <run-id>` (v0.6.3, F-09: the updated-row requirement binds HERE, where the work that updates the row has happened; the sweep form is a consistency lint at every other gate; since v0.7.4 the close form also demands step 2's walk artifact, prodsim/F-86) — and sweep: `scripts/wow/gates.sh sweep --run <run-id>`. P4 artifacts (reconciled SPEC v<N+1>, divergence-G4, RUN-REPORT) commit under the bare lane form `[T:<run-id>]` (F-10) — never a borrowed task id.
5. **Audit triggers** (counters from status.mjs, recorded here). The table must parse back (v0.7.3, prodsim/F-74 — the natural row shape was unreadable by the deriver, which then said 'not recorded' about a recorded table; the pattern now accepts prose beside the id and a verdict beside the number, but the AT-id must LEAD cell 1 and an integer must LEAD cell 2; since v0.7.5 bold decoration around either is tolerated and the heading may carry a suffix, platform/F-87 — but rows are TABLE rows: a bullet list reads as "section present, 0 table rows"). A literal example row (v0.7.5, prodsim/F-100: the example cites a stand-in inventory diff, not a path count):

   `| AT-1 stand-ins for real systems committed this run | 0 — threshold >3, NOT HIT | ev:cmd{git diff --diff-filter=A --name-only wow/<id>/base..wow/<id>/int -- src/ | grep -iE 'mock|stub|fake' | <the repo's stand-in classifier, committed under evidence/ORCH/> => new stand-ins 0 @2026-09-19} |` (the classifier is consumer-shaped and committed with the run; the package ships none — DEV-R12-12)

   - AT-1: **stand-ins for real systems** added **>3 this run** — the role, not the path (P3 RUN-REPORT structure lists what is and is not a stand-in; prodsim/F-100)
   - AT-2: **remediation cycles >5 cumulative on this spec since last audit** — ONE cycle = ONE trigger (a park, a gate rejection, a verifier report whose findings forced a fix wave, or a review round that did) together with every commit answering it; a commit answering two triggers belongs to both; PO-authored plan amendments do NOT count, unit fix waves and ORCH fix-forward amendments DO; the window is this run's P1–P4 plus any repair made after the row was recorded (which counts toward THIS run's figure, re-recorded, not the next audit's); a fix iteration `r>1` of the same spec continues the count. The row's citation is a RUNNABLE command over a stated range of COMMITTED artifacts — `PARK-` ids and `repairs VF-` labels in `reports/*.md`, FAIL grades in `*-verify.md`, `DEV-ORCH-` records, the plan's `reviews:` field; the gate log is untracked and is NOT a citable source — never prose or a list of names; GATE-7 refuses an AT-2 row with no `ev:cmd` (v0.7.5, platform/F-101 + prodsim/F-91: two readings of the undefined term gave 0 and 6 on one run, straddling the threshold; two archived figures could not be reproduced; DEV-R12-12). A workable command: `git grep -ohE 'PARK-U[0-9]+-[0-9]+|repairs VF-U[0-9]+-[0-9]+|DEV-ORCH-[0-9]+' runs/<id>/reports | sort -u | wc -l`, plus the FAIL-graded verify reports.
   - AT-3: BLOCKERs **>1 this run** (derived from the RUN-REPORT's status rows; the audit-triggers section's own text is never counted — platform/F-99; for an archived run status.mjs reads the recorded value back — platform/F-88)
   - AT-4: stale `file:line` refs found by sweep **in docs not modified this run** ≥3 (commit-time drift is GATE-5's job — no double role)
   - AT-5: **any** AC that passed for the wrong reason
   - AT-6: ORCH context clears **>2 this run** (v0.7.5, non-negotiable #8) — a clear is a FORCED restart inside a phase (context exhausted or compacted); a planned phase entry in a new session is not one (DEV-R13-05). Read from HANDOFF `## resume` `clears:` (FORMATS §8) until this row records it; a self-report by the ORCH (ADV-R13-09). status.mjs prints `not derived` / `null` with the note when the line is absent — unrecorded is not zero, and **GATE-7 at P5 refuses a RUN-REPORT that records fewer rows than there are triggers** (R13b, ADV-R13-06), so every trigger gets a row here. A hit is a FRAMEWORK finding as well as a GAPS record: the row names the step that consumed the context and why it was not delegated (FORMATS §14), and the finding is filed upstream as pilot feedback.
   **The trigger outcome is an obligation, not a report line:** any hit is recorded at P4 as a GAPS.md record (FORMATS §12) — typically `effect: blocks-new-feature-work`, discharge = the audit phase completing — so it survives run archival and GATE-12 enforces it. The RUN-REPORT row merely cites the record.
   Any hit → schedule an audit phase before new feature work.
