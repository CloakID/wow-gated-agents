# P5 — PUBLISH — DRAFT v0.7.4
Entry: `/wow-publish <run-id>` · Mechanical; low tier · Output: clean durable docs, closed tracker, archived run.

## [ORCH]
0. **Merge to `main` — this step owns it** (v0.6.2, F-11: previously the merge belonged to no phase; a run could pass G4, archive itself, and never be on `main`). Merge `main` into the run branch, resolve, then open the PR or fast-forward per `merge_to_main` in wow.config.json. Before step 3 because archiving a run that never reached `main` is worse; before step 5 because step 5 is destructive (below).
1. Durable docs: final SPEC version confirmed in `docs/spec/`; extract accepted decisions into `docs/adr/` (immutable, numbered); update `docs/codebase/` front-matter for touched areas; confirm GAPS current and the archived run's RUN-REPORT + `reports/` intact (the traceability home — F-11).
2. Jira: close accepted epics/stories/tasks; archive per PO convention ("closed and archived for reference"). Apply any queued ops from `jira-queue.md`.
3. Archive `runs/<run-id>/` (move to `runs/archive/` or tag — per wow.config). HANDOFF of the archived run is retired; nothing in `runs/archive/` is load-bearing. **Delete the run's branches — local AND remote** (v0.7.2, platform/F-63: they are different states and an operator who deletes one assumes the other followed; one pilot accumulated 25 dead refs over five months, `base`/`int` on origin with the unit branches local-only, invisible from either side alone). Order it after step 0's merge is confirmed — deleting `int` is what stops the merged PR being reopened. A surviving `wow/<run-id>/*` ref is a second, MORE discoverable home for content the archive owns; GATE-7 `--p5` refuses the publish while one exists. **Archival is a P5 step, not an escape hatch** (v0.7.3, platform/F-65's named exposure): moving a red run under `runs/archive/` by hand silences gate-3/gate-5 for it by design — archived runs are graded under the vocabulary of their time — so a run reaches the archive only THROUGH this phase — and this phase's own sweep (step 6) grades the run FROM the archive: at `--p5` the run named by `--run` is walked wherever it sits, so the archived state, not a pre-archive snapshot, is what the escrow certifies (v0.7.4, platform/F-77 + prodsim/F-88: two pilots independently hit step 6 refusing the run step 3 had just archived, and one invented an un-archive/re-archive dance around a destructive-adjacent step to get a real reading).
4. GC: list stale quick stubs (FORMATS: empty `result` >7 days) and unresolved debug files → PO confirms deletion/retention. Nothing deleted silently. **A file cited by `docs/GAPS.md`, `docs/REQUIREMENTS.md` or any other registry is NOT a stale stub, whatever its `result` cell says** (v0.7.4, platform/F-80: seven cited proofs were GC'd and the loss was invisible for twelve days — a deleted proof looks exactly like a proof that never existed): it is excluded from the candidate set, or named to the PO as an exception with the citing row quoted — one grep per candidate, no judgement in it. GATE-7 at `--p5` refuses a publish whose registries cite a target that exists at neither its path nor the archive rewrite of it. **Before repairing a dead citation, establish what the absence MEANS** (platform/F-81): `git log --follow` / `--diff-filter=D` says whether the target was renamed (repoint) or deleted (restore) — both treatments were once applied to one file in one commit, and the wrong one is silent (FORMATS §3).
5. Regenerate `.claude/settings.local.json` from `scripts/wow/permissions-policy.json` as a **reviewed merge, never a wipe** (v0.6.3, F-06: the playbook said 'accreted entries dropped' while INSTALL said reviewed merge, and a literal reading would have stripped every permission a pilot's verify commands depend on — 18 designed vs 234 accreted, overlap zero): diff accreted entries against the designed policy, carry what the repo's checks actually use, drop the rest with the drops listed for PO review; record the merge in a committed note, because the settings file is gitignored and leaves no reviewable trace. **Destructive by design, so it refuses on a branch behind `main`** (v0.6.2, F-11 — GATE-7 at `--p5` enforces this): it regenerates from the tree it runs in, and a grant that landed on `main` through another lane would be silently dropped. Step 0 is what makes this step safe.
6. Run the **P5 sweep** — `scripts/wow/gates.sh sweep --p5 --run <run-id>` — then `node scripts/wow/status.mjs`; commit `[WOW:publish]`. `--p5` is what adds **GATE-7** (unresolved `jira-queue.md`, stale quick stubs, archive state, phantom empty run dirs, the behind-main refusal, the obligation-escrow check — nothing obligation-shaped may live only in the run being archived, FORMATS §12 — and the registry-citation check, platform/F-80) to the sweep: mid-run those are legitimate, at publish they are not. `--run <run-id>` names the run this phase is publishing; at `--p5` GATE-7 grades it from `runs/archive/` (step 3 has moved it there) — that is the success condition of the phase, not an operator error (v0.7.4, platform/F-77). Outside `--p5`, archived runs stay exempt (F-36) and graded under the vocabulary of their time (platform/F-65).
