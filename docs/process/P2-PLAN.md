# P2 — PLAN — DRAFT v0.7.5
Entry: `/wow-plan <run-id>` · Output: `runs/<run-id>/PLAN.md` (ORCH-owned, machine-parseable per formats.json `plan_schema`) · Gate: **G2 = GATE-8 + GATE-13 lint → adversarial review → PO sign-off** → Jira stories/tasks.
Load: signed SPEC, `docs/codebase/<area>.md`, CONVENTIONS, sibling-unit contracts if replanning — **and, for a fix iteration `r<N+1>`, the previous run's verify reports' VF and observation lists and its CV records, read for any that bind a task this plan re-plans** (v0.7.5, platform/F-104: a lesson one run paid a fix wave to learn reached the next run's plan only if the planner remembered it; two of three fix waves in one lineage repeated defects the prior run had recorded). The plan review asks "which prior-run VF/CV ids bind this task?" and the answer is ids or "none", with its denominator.

**Entry condition — resume before re-plan** (v0.7.3, platform/F-68): if a prior run of this spec carries a **signed, unexecuted unit** covering this work (a wave parked before it began), the default is to carry that unit forward with a delta — its contracts, tasks, verifies and non-vacuity cells absorbed review already, and the delta needs scrutiny only where the world moved. Re-planning it from scratch is a recorded decision with its reason. The measured cost of the missing rule: seven review rounds re-derived and three more rounds re-opened questions the original had settled.

## [ORCH] — decompose
1. Split into units `U<n>`, sized for **independent verifiability**, not minimality. Per unit:
   - **file-ownership list** `owns:` (paths it may write; ORCH-owned files excluded per FORMATS §9);
   - **`areas:`** — the codebase areas the unit touches (FORMATS §6) and **`deps:`** — the external dependencies it relies on (FORMATS §11). These are GATE-6's input: a plan that declares no `areas:` fails the gate rather than passing with nothing to check;
   - **interface contracts** (signatures/schemas/events), frozen at G2;
   - **`inputs:`** — the paths this unit READS that another unit produces (v0.7.2, F-58). GATE-8 checks each against the other units' `owns:` at a STRICTLY lower wave — a re-dispatched producer's outputs count as available at its `dispatched_at_wave:`, the fail-safe reading (ADV-R12-07); an input with no producer, or a same-wave producer, fails at G2 where the cost is a revision — eight plan revisions and seven adversarial review rounds missed one, because the dependency is invisible from the unit sections alone. An ORCH-written run record under `runs/<id>/orch/` is declarable with no producer unit (v0.7.5, prodsim/F-108); its existence on `int` is checked at the consuming wave's boundary (`gate-8 --run <id> --boundary <wave>`). **Every repo path a task's Action or Verify names is held to the same rule** (v0.7.5, platform/F-97: 9 of 11 traced plan defects — a clause naming a file no task writes, an ORCH-owned file that does not exist during P3, an unallocated id — survived every adversarial round, in runs with 5 and 7 rounds; all were decidable from the plan text): GATE-8 refuses a path that is not tracked at HEAD, not under the unit's `owns:`/`inputs:`/own reports-and-evidence, and not owned by a lower-wave unit (a lower-wave unit's `reports/`/`evidence/` files and the archive's prior-run ids count as delivered — ADV-R12-09), and refuses a `PARK-`/`DEF-plan-`/`AM-`/`CV-` id nothing allocates; `lint-ok: <reason>` in the cell is the visible escape. On a SIGNED, committed plan the lint reads only rows added or changed since the signing commit, like GATE-13 (DEV-R12-09);
   - task list `T<nn>` — action · verify (`ev:cmd` template) · done-means;
   - **autonomy contract** (decide-and-log vs park; cross-unit/AC-touching/irreversible always park);
   - model tier and wave assignment. `wave:` is where the unit's outputs first become available (what the F-58 rule reads); a unit RE-DISPATCHED at a later boundary by a mid-run plan amendment (P3 §branch & merge model) records that boundary as `dispatched_at_wave:` and may then read any lower wave's outputs (v0.7.5, prodsim/F-104).
2. Dependency/wave order; **serial integration wave last** with its own tasks + verifies; branch model per P3 (base/U<n>/int).
3. **AC↔task coverage matrix** (required — GATE-8 checks totality).
4. New invariants/checks ship with non-vacuity proofs (GATE-4) — written as `invariant: <claim>` lines paired with `non-vacuity: <proof citing ev: or a file>` in a run artifact; GATE-4's per-run arm counts exactly those markers and says VACUOUS when a run declares none (v0.7.5, platform/F-84: 14 of 14 pilot runs declared zero, and nothing said so).
5. **Feasibility preflight** (v0.7.5, prodsim/F-109) for any task whose Verify runs a live leg or depends on captured evidence: before G2 (and before a mid-run plan amendment is signed, P3 §branch & merge model) the ORCH reads the design against the current code and the captures already on disk — read-only, FACT/INFERENCE/UNDETERMINED-labelled, committed as `runs/<id>/orch/preflight-<n>.md`. A design that depends on a capture field the preflight records as absent is flagged before it is signed (4 of 9 proof runs in one amendment were infeasible as written). The P2 reviewer gets this file as a second input, without the codebase.
6. Record the G2a review rounds in the plan preamble as `reviews: <n>` (v0.7.5, platform/F-97 fix 3: status.mjs prints it; 7 of 14 pilot plans retained no review record).

## [ORCH] — G2a: lint, then review
1. Run **GATE-6**, **GATE-8** and **GATE-13**, in that order — all mechanical, all cheap:

   ```sh
   scripts/wow/gates.sh gate-6 --run <run-id>   # areas: + deps: freshness (FORMATS §6, §11)
   scripts/wow/gates.sh gate-8 --run <run-id>   # ownership, coverage totality, verify commands, schema
   ```

   GATE-8 checks ownership overlaps (incl. ORCH-owned files — `runs/*/orch/*` and `walk-G4.md` are ORCH-owned since v0.7.5, FORMATS §9), coverage-matrix totality against the SPEC's AC rows, a verify command in every task's **Verify** column (located by header, not position), that PLAN.md parses against `plan_schema`, and (v0.7.5) the reads-vs-declarations rule above. Fix until green — reviewer time is not spent on grep-able defects.
   Each unit declares `governs:` — the requirement ids its work updates; declarations (with the spec's `requirements:` header) ARE GATE-2's obligation set (v0.6.4, F-17). A Verify may contain `|` **escaped as `\|`** (v0.6.4, F-18 — an unescaped pipe splits the cell and GATE-8 now names that cause), or route through a file under the unit's evidence dir, which also retains the intermediate output. The RUNNABLE command is `scripts/wow/gates.sh verify-cmd <task-id>` — the cell with its escapes removed and any `lint-ok:` marker dropped, as GATE-13 reads it (v0.7.5, prodsim/F-111: an executor ran the cell with the escapes in place and did not get the signed result). A command that needs a LITERAL `\|` (a BRE alternation) cannot be spelled in a cell — route it through a script file under the unit's evidence dir (ADV-R12-17).
   A rule that binds **every** unit goes in the plan's `## Contracts` block — P3 appends it to every executor manifest; normative language anywhere else outside a unit section reaches nobody and GATE-8 rejects it (v0.6.3, F-28). Tasks whose evidence cannot be re-derived by a verifier (destroyed by the procedure, credential contractually human-held, destructive to re-run) are marked `audit-only: <why>` in the plan — HERE, in front of the PO at G2, never by the ORCH at verifier-spawn time (v0.6.3, F-30).
   **GATE-13** (v0.6.2, F-9) checks the task table's **Non-vacuity column** — one cell per task naming a plausible wrong answer the Verify rejects, citing something runnable, or `MANUAL` — and lints Verify cells for idioms that each shipped a real inert check (`lint-ok: <reason>` accepts one deliberately and visibly). This is the discipline G2a review applies ad hoc, required uniformly and machine-checked: a Verify never shown failing is only believed to check — read per CLAUSE where a Verify chains several (v0.7.5, prodsim/F-92 amendment: the RED case reaches each clause that invokes a tool with flags, or at least the clause the AC's words name). On a SIGNED plan GATE-13 lints only the rows added or changed since the signing commit — rows signed at G2 stay frozen, amendment rows are not (v0.7.5, prodsim/F-107: eight amendments, four inert verifies, every amendment commit green). The `||` form is no longer a merge-base guard (v0.7.5, platform/F-86: it collapses git's 128/129 harness-fault exits into the verdict exit 1; resolve the operand first, or capture `rc=$?` on the same line).
2. Spawn reviewer AGENT (fresh context; input = SPEC + PLAN only). **Judgment scope only:** contract gaps between units · premise checks on plan-level verifies ("does this verify test the product or the harness?") · unit-sizing sanity · autonomy-contract adequacy vs risk. Findings → revise → delta re-review (FORMATS §7).

## [PO] — G2b sign-off checklist
Unit boundaries sensible · autonomy contracts match risk appetite · irreversible actions parked-by-design · tier assignments acceptable.
Close: Jira transition + `signed: <date> ev:jira{…}` in PLAN header, then verify it mechanically — `scripts/wow/gates.sh gate-9 --gate G2 --run <run-id>` (with `--gate`, the record is required, not merely consistent). The freeze GATE-13 and GATE-8's reads lint honour is the signing COMMIT's: an uncommitted signature line freezes no row (GATE-9's `--gate` check asks only whether the record is present — commit it in the same step).

## [ORCH] — on sign-off
GATE-10 divergence diff first — write `runs/<run-id>/divergence-G2.md` (Item | Git | Jira | Classification) and check it with `scripts/wow/gates.sh gate-10 --run <run-id> --gate G2`; classify any git↔Jira difference per FORMATS §10. Then create stories per unit, tasks per task, parent-linked; bodies carry PLAN excerpts + links. Record `ev:jira{…}`. Run the gate sweep at the gate: `scripts/wow/gates.sh sweep --run <run-id>`.
