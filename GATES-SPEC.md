# GATES-SPEC — mechanical enforcement (single home for rules) — DRAFT v0.7.2

> Implemented as `scripts/wow/gates.sh` (engine: `gates.py`). Hook placement matters: **GATE-1 runs in the `commit-msg` hook** (the message doesn't exist at pre-commit); **GATE-5 runs in `pre-commit`** (staged files). Hooks are installed where git actually reads them — `core.hooksPath` if the repo sets one, else the common git dir, so they are **inherited by every worktree** — executors get enforcement for free. Full sweep (`gates.sh sweep`) runs at every gate; P5 adds GATE-7 via `sweep --p5`. Patterns/vocabulary/schemas come from `scripts/wow/formats.json` — consumed by **both gates.sh and status.mjs**; neither script contains inline formats. Process docs reference gates by ID and never restate them. Every gate has a negative test in `scripts/wow/tests/`; a gate whose negative test doesn't fail when the gate is disabled is itself a defect (inert-gate class — recurred 3× under GSD). **Subject-absent is never a pass (added v0.5.3, PF-04):** every gate must go red — or explicitly refuse to run — when the artifact it checks is missing or unparseable. Each gate therefore carries TWO negative tests: violation-present (the gate fires on a planted violation) and **subject-absent** (the gate refuses when its subject doesn't exist — a missing PLAN.md, a missing or unreadable registry, an unreadable map — an EMPTY registry table is a valid registry: the absence that never passes is the file or its readability, not its row count (verifier F7)). Origin: GATE-6 returned PASS for a run id with no PLAN.md because zero parsed units skipped the "declares no areas" branch — the inert-gate class reappearing inside the engine that exists to kill it.

**Layer parity (added v0.5.3, PF-05):** a process-doc change that names a gate or schema is permitted to land ahead of its engine counterpart ONLY with a paired open obligation in `docs/GAPS.md` (FORMATS §12) recording the unimplemented enforcement. The sweep checks parity mechanically (`check_parity`, first entry of every sweep; `gates.sh parity` runs it alone): every gate ID in this table exists in the engine registry, every schema-family name (`*_schema`, `*_frontmatter`, `*_row` tokens this spec mentions) exists in formats.json — full both-direction coverage of every named key is OBL-PKG-17's round — and version stamps agree with the CHANGELOG authority (N2); or an open obligation covers it. Origin: v0.5.2 declared GATE-12, the GATE-7 escrow, and `gap_row`, and none of it reached gates.py/formats.json; nothing caught the split. **Reverse direction for lane refs (added v0.6.1, pilot #2 PF-b):** the sweep also asks "do the docs have what the engine declares?" — every commit-trailer kind in `formats.json` must be documented (its `doc_literal`) in `docs/process/LANES.md` AND in the resident router section, or parity fails. Origin: `[WOW:migrate]` existed in engine, tests and INSTALL, and was invisible to an operator working from the router — at exactly the moment it was the only legal lane. Full named-key coverage both ways remains OBL-PKG-17's round. **Registry successor staleness (engine round 6b, OBL-PKG-21):** parity also fails an OPEN registry row whose successor cell names an already-shipped version — a version stamp pointing backward: the named event happened and did not discharge the row, so the cell is fiction (four real rows aged this way across four versions before the 2026-09-13 audit caught them). Backticked versions in the cell are mentions of history; round labels are not machine-comparable and stay a monthly-audit checklist item (CONTRIBUTING §Release quality). **Dialect portability (v0.6.4, F-35):** formats.json is one home read by two regex engines, and a shared regex is only shared if both read the same dialect — the sweep refuses the non-portable end/start-of-string escapes (backslash-Z / backslash-A) anywhere in the file; one such key had gates.py and status.mjs disagreeing whether the same repo held 0 or 16 stale quick stubs.

**Gate logic and gate wiring are separate claims:** `tests/test-install.sh` installs into a throwaway repo (including one using `core.hooksPath`, and one with a pre-existing hook) and drives real commits through the real hooks. A gate with a perfect negative test that nothing calls is inert.

| GATE-1 | Commit message contains exactly one lane ref (`[T:]`/`[Q:]`/`[D:]`/`[WOW:publish]`) and it **resolves to a real record**: `[T:]` must name a task *row* in `runs/<id>/PLAN.md` (a task id in prose or a comment does not resolve), `[Q:]` an existing dir, `[D:]` an existing debug file. The bare form `[T:<run-id>]` resolves to the run **directory** and carries a run's phase-level artifacts (v0.6.3, F-08/F-10). Trailers quoted in a `git commit -v` diff, in backticks, or in fenced/indented blocks are **mentions and are not counted** (F-07) — the most relevant commits are the ones about lane behaviour, and they must be writable. **A zero-hit message is diagnosed, not just refused** (v0.7.1, F-46/F-39): when the message carries a trailer-SHAPED token that matches no lane pattern, the error names that token and the real cause — a slug over the cap (derived by probing `ids.run_slug`, never restated — audit A1), or a task tail the grammar cannot express — instead of "missing lane ref", which sent a pilot hunting the wrong defect for a full cycle. Every id shape GATE-1 matches is expanded from the named-parts anatomy (`ids.run_date`/`run_slug`/`run_iter` → `run_core`) at load, so neither the shape nor the cap can be restated inconsistently; `gates.sh check-id <run-id>` applies the same rule at run open, before anything is signed against the id | **commit-msg hook** | block commit |
| GATE-2 | Phase close: every requirement ID named by the active spec/plan has an **updated** technical-status row in `docs/REQUIREMENTS.md` — the row must appear in this run's diff, not merely exist. **Two forms (v0.6.3, F-09, mirroring GATE-9):** the sweep form is a consistency lint — named ids have rows, unreadable rows loud; `--close` (at G4/P4, and in the P5 sweep) adds the updated-row requirement, because at G2 no work has run and the gate had no phase where it was both in scope and satisfiable. Sweeps with no `--run` resolve the active run rather than checking nothing. The id shape is **repo-configurable** (v0.6.1, pilot #2 PF-d): `requirement_id` in `wow.config.json`, defaulting to `ids.requirement` (`REQ-nnn`) — a brownfield repo keeps its stable identities instead of renumbering or running a permanently-vacuous gate. Id-shaped REQUIREMENTS rows the effective pattern cannot read FAIL loudly (FR-1's rule), never parse as an empty-and-permissive set. **The obligation set comes from declarations when they exist** (v0.6.4, frisbii F-17): a spec-header `requirements:` line and/or unit `governs:` lists ARE the set — mention is not claim, ranges enroll every row they cover, and a gated doc can discuss an id without adopting it; with no declaration the legacy text scan applies, with an advisory nudge. An explicitly named run that resolves to no plan, active or archived, reports **UNGRADED (red)** — archiving must not launder a failing gate into a passing one (F-36) | gate sweep | block gate |
| GATE-3 | Evidence-required statuses (`COMPLETED`, `FAILED` — FORMATS §4) and done-words carry a **well-formed** `ev:` citation in the same row/sentence, and reference-class statuses (`BLOCKED`/`PARKED`/`DEFERRED`) carry their required reference. A citation that does not match its type's shape (`ev:cmd{no command => no result}`) does not count. **Inline code is a mention, not a claim (v0.6.1, pilot #2 PF-a):** anything inside backticks is neither flagged as malformed nor accepted as satisfying evidence — a self-describing doc may show citation templates, and a backticked citation cannot green a status. Fenced blocks were already skipped. Citation bodies admit **one level of balanced braces** (v0.6.2, frisbii: `awk '{…}'`, jq objects and regex quantifiers are citable; deeper nesting is reported as *the format cannot express this*, never as the writer's citation being malformed). **Verdict columns are not status columns** (v0.6.2, F-10): a Grade/Verdict column is checked against `verdict_vocab` (`PASS` / `PASS-with-carry-forwards` + CV id / `FAIL` + VF id) — a status describes the work, a verdict judges it, and COMPLETED+FAIL is the run's most important pair. A status-shaped cell that is not gradeable (uppercase status token + trailing prose) **fails instead of falling through** (v0.6.3, F-14); an `ev:` token of an **unknown kind fails loudly** instead of being invisible (F-27, `ev:attest` added for human decisions); the inline-code mask is document-wide, so spans wrapping a line break stay mentions (F-05). **A DECLARED status section whose table resolves no Status/Grade column fails naming the section** (v0.7.2, F-14 addendum): a report section listed in `report_row_schema.sections` holding a `| id | what |` table was graded by NOTHING — the cheapest silent shape, needing only the columns that read most naturally; the gate knows the section is a status section before it reads a row, so this is subject-absent one level down. **A fully-backticked table cell outside a Status/Grade column is a mention** (v0.7.1, F-41): a verdict-comparison table ("the executor wrote `COMPLETED`, the verifier graded `FAIL`") quotes status words as objects of discussion, and rejecting it made the run's most important comparison unsayable — Status/State/Result and Grade/Verdict columns keep their claims-by-position rule, so a backticked status can never green a real row. Scanned docs: RUN-REPORT, report files, SPEC ACs, REQUIREMENTS rows, quick NOTE results, GAPS.md. **Enforced subset only** — claim-label discipline is convention, not gated | gate sweep | block gate |
| GATE-4 | Every invariant/check added or modified in this run has a recorded non-vacuity proof, and the proof **cites something runnable** — an `ev:` citation or an existing file. `non-vacuity: yes` is not a proof. Also checks the suite still holds one negative test per gate plus the wiring test | gate sweep | block gate |
| GATE-5 | `file:line` citations **in files modified by this commit/run** pass preflight (match/drifted/gone), judged against the **staged** content at pre-commit — not the worktree, which can differ from what is about to land. Sweep-found drift in *unmodified* docs is NOT blocking — it is reported as an advisory and is the source status.mjs reads for audit-trigger counter AT-4 (P4) | **pre-commit** + sweep | block commit/gate |
| GATE-6 | Main-lane plan requires (a) codebase-map freshness per FORMATS §6 (git rule) for every area the plan declares in `areas:` AND (b) external-dep map freshness per FORMATS §11 (probe-hash rule; `max_age_days` fallback) for every dependency it declares in `deps:` — or a P0 completion record in HANDOFF. A plan that declares no `areas:` fails: the gate then has nothing to check, and that is not a pass. Front-matter accepts inline AND block-list `paths`; a map whose paths resolve empty or whose `verified_against` does not resolve **fails loudly** (v0.6.3, F-12: an empty pathspec made git refuse the command, the helper swallowed stderr, and a freshness gate could never go stale — it was observing a failed invocation, not a clean history). A dep map's `probe:` must match the allowed command pattern (`probe_allowed`; wow.config.json `probe_command_pattern` override) — checked **before** execution, never run when disallowed, never falling through to the calendar branch (v0.6.2, frisbii S-2: a probe that wrote a marker file ran, and the gate passed). **Freshness is content-based** (v0.7.1, F-45): the verdict is `git diff --quiet <verified_against> HEAD -- <paths>` — commits that touch mapped paths but leave the tree identical (merge ripples, revert pairs) are reported informationally, never as stale; the stale message states the content differs and the commit count | at `/wow-plan` | block plan |
| GATE-7 | P5 sweep: no unresolved `jira-queue.md`, no un-GC'd stale quick stubs, archive state consistent, **and obligation escrow: every obligation the run created (DEFERRED rows, audit-owed outcomes, CV records with future discharge) exists in a durable home status.mjs reads (GAPS.md/REQUIREMENTS) — nothing obligation-shaped may live only in the `runs/` tree being archived**. Also (v0.6.2): **no phantom runs** — a run-id directory holding no files at all (the empty shell archiving strands, frisbii S-6) is refused, and status.mjs skips it; **not behind main** (`--p5` only, F-11) — P5 step 5 regenerates permissions destructively from the current tree, so publishing from a branch behind the published branch (`main_candidates`; wow.config.json `main_branch` override) is refused until P5 step 0's merge. The escrow walk is **scoped to the named run** and the archive exemption compares real paths, not a template (v0.6.4, F-36 — every archived run was being re-scanned forever, and a publish failed on another mid-flight run's CV ids its own G4 had not judged). Phantom classification asks git three questions (S-6 addendum): tracked ⇒ run; untracked-unignored ⇒ run mid-creation; only-ignored or empty ⇒ leftover, refused — and a destructive instruction never depends on ignore configuration. At `--p5`, if a feedback log exists, every logged `F-nn` must have a write-up under the upstream dir (F-37). **The escrow PARSES the registry** (v0.7.0, OBL-PKG-13): a CV needs a row with that id (a mention in another row's prose is not a row), a shorthand `CV-<nn>` resolves to the run's full id and demands the full-form row, a DEFERRED task needs an open row referencing it, and **an audit-trigger hit recorded in the RUN-REPORT needs an open row naming its `AT-n`** (F8's third class) — or the obligation retires with the archived run. **The escrow reads status by column header** (engine round 6, OBL-PKG-20/audit: the DEFERRED walk read `cells[1]` positionally — status-by-header was OBL-PKG-13's own discharge rule, applied to gate-3 but not to the escrow's walk, so a DEFERRED in any other named Status column retired silently with the archived run; a table without a named Status column is checked in full, gate-3's convention applied uniformly). **A CV discharged in-run is a closed question** (v0.7.2, F-51): the escrow exempts a record whose own block carries `discharged: <date> ev:…` — a CV is obligation-shaped only while its discharge is future, and demanding registry rows for eight already-closed records filled the registry of open obligations with records that owe nothing; an UNevidenced `discharged:` stays demanded, loudly. **Archived runs leave no branch refs** (v0.7.2, F-63, `--p5` only): a `wow/<run-id>/*` ref surviving its run's archival is a second, more discoverable home for content the archive owns (25 dead refs accumulated in one pilot over five months) — publish is refused until local refs are deleted; the P5 clause says local AND remote. **A gap row with MORE cells than the schema is refused naming the real cause** (v0.7.1, F-44): an unescaped `|` inside a cell — a pipe in an `ev:cmd`, the exact shape §12's escape rule exists for — used to silently truncate the row under zip(), and a well-formed-looking registry lost its discharge column. Runs as part of `gates.sh sweep --p5` | at P5 (`sweep --p5`) | block publish |

**formats.json content spec (single machine home, dual consumers):** `ids` (EVERY key under `ids` — the enumeration is the file's own key set, not a restated list: F-55 found the restatement eight keys short with the no-inline rule scoped by it, so eight families sat outside the rule that exists to keep them in one home) · `paths` (every repo-relative location the engines read) · `commit_trailers` · `branch_patterns` · `status_vocab` + forbidden synonyms + status columns · `claim_labels` · `evidence` types (each occurrence is shape-checked) · `scan_targets` (the gated document set) · `codebase_frontmatter` schema incl. the `p0-record` escape hatch · `dep_frontmatter` schema (FORMATS §11) · **`plan_schema`** (units, ownership lists, coverage matrix, tasks w/ verify, column names) · **`report_row_schema`** · **`requirements_row_schema`** · `jira_mapping` (FORMATS §10 table, divergence-record columns, closing gates) · `non_vacuity` (invariant/proof markers, test-file naming) · `legacy_freeze` · `runs_layout` · `audit_triggers` (incl. how each is derived — from durable homes, never archived RUN-REPORTs) · **`gap_row`** schema (taxonomy, owner, `effect` closed vocab: advisory | blocks-new-feature-work | blocks-install — consumers GATE-12 and install.sh respectively; an unrecognized effect value FAILS validation loudly, it is never treated as non-blocking — `scope` for blocks-install rows (repo list or `*`), successor, discharge) · `install` (what a complete installation is) · `sweep` (which gates run in a sweep, and which only at P5) · `verify_lint` (GATE-13's inert-Verify idioms + accept marker) · `status_vocab.verdict_vocab` / `verdict_columns` (the verifier-verdict vocabulary GATE-3 checks Grade/Verdict columns against).

**The no-inline rule is testable:** a literal regex, path or status word in `gates.py` or `status.mjs` that belongs to one of those keys is a defect. Two consumers with private copies of a format is how enforcement and status derivation drift apart, which is the failure this whole file exists to prevent.

**Recovery on any gate failure:** FORMATS §7. **Explicitly not gates (judgment — ORCH/PO):** premise-check quality, unit sizing, autonomy-contract scope, contract-gap review, classification decisions, decision-vs-fact classification of blocking spec questions (P1 probe route), claim-label quality. A gate that pretends to check judgment is theater.
