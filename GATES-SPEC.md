# GATES-SPEC — mechanical enforcement (single home for rules) — DRAFT v0.5.0

> Implemented as `scripts/wow/gates.sh` (engine: `gates.py`). Hook placement matters: **GATE-1 runs in the `commit-msg` hook** (the message doesn't exist at pre-commit); **GATE-5 runs in `pre-commit`** (staged files). Hooks are installed where git actually reads them — `core.hooksPath` if the repo sets one, else the common git dir, so they are **inherited by every worktree** — executors get enforcement for free. Full sweep (`gates.sh sweep`) runs at every gate; P5 adds GATE-7 via `sweep --p5`. Patterns/vocabulary/schemas come from `scripts/wow/formats.json` — consumed by **both gates.sh and status.mjs**; neither script contains inline formats. Process docs reference gates by ID and never restate them. Every gate has a negative test in `scripts/wow/tests/`; a gate whose negative test doesn't fail when the gate is disabled is itself a defect (inert-gate class — recurred 3× under GSD). **Gate logic and gate wiring are separate claims:** `tests/test-install.sh` installs into a throwaway repo (including one using `core.hooksPath`, and one with a pre-existing hook) and drives real commits through the real hooks. A gate with a perfect negative test that nothing calls is inert.

| ID | Check | Where | On fail |
|---|---|---|---|
| GATE-1 | Commit message contains exactly one lane ref (`[T:]`/`[Q:]`/`[D:]`/`[WOW:publish]`) and it **resolves to a real record**: `[T:]` must name a task *row* in `runs/<id>/PLAN.md` (a task id in prose or a comment does not resolve), `[Q:]` an existing dir, `[D:]` an existing debug file. Trailers quoted in a `git commit -v` diff are not counted | **commit-msg hook** | block commit |
| GATE-2 | Phase close: every REQ ID named by the active spec/plan has an **updated** technical-status row in `docs/REQUIREMENTS.md` — the row must appear in this run's diff, not merely exist. Sweeps with no `--run` resolve the active run rather than checking nothing | gate sweep | block gate |
| GATE-3 | Evidence-required statuses (`COMPLETED`, `FAILED` — FORMATS §4) and done-words carry a **well-formed** `ev:` citation in the same row/sentence, and reference-class statuses (`BLOCKED`/`PARKED`/`DEFERRED`) carry their required reference. A citation that does not match its type's shape (`ev:cmd{no command => no result}`) does not count. Scanned docs: RUN-REPORT, report files, SPEC ACs, REQUIREMENTS rows, quick NOTE results. **Enforced subset only** — claim-label discipline is convention, not gated | gate sweep | block gate |
| GATE-4 | Every invariant/check added or modified in this run has a recorded non-vacuity proof, and the proof **cites something runnable** — an `ev:` citation or an existing file. `non-vacuity: yes` is not a proof. Also checks the suite still holds one negative test per gate plus the wiring test | gate sweep | block gate |
| GATE-5 | `file:line` citations **in files modified by this commit/run** pass preflight (match/drifted/gone), judged against the **staged** content at pre-commit — not the worktree, which can differ from what is about to land. Sweep-found drift in *unmodified* docs is NOT blocking — it is reported as an advisory and is the source status.mjs reads for audit-trigger counter AT-4 (P4) | **pre-commit** + sweep | block commit/gate |
| GATE-6 | Main-lane plan requires (a) codebase-map freshness per FORMATS §6 (git rule) for every area the plan declares in `areas:` AND (b) external-dep map freshness per FORMATS §11 (probe-hash rule; `max_age_days` fallback) for every dependency it declares in `deps:` — or a P0 completion record in HANDOFF. A plan that declares no `areas:` fails: the gate then has nothing to check, and that is not a pass | at `/wow-plan` | block plan |
| GATE-7 | P5 sweep: no unresolved `jira-queue.md`, no un-GC'd stale quick stubs, archive state consistent. Runs as part of `gates.sh sweep --p5` — a mid-run queue legitimately has open items, so it joins the sweep only at P5 | at P5 (`sweep --p5`) | block publish |
| GATE-8 | **Plan structural lint** (mechanized reviewer checks, runs before G2a review): (a) no ownership overlap between unit path lists, and no unit claims an ORCH-owned file (FORMATS §9); (b) AC↔task coverage matrix present and total (every SPEC AC mapped); (c) every auto task has a verify command. PLAN.md must parse against the plan schema in formats.json | at G2, pre-review | block review |
| GATE-9 | **Gate-closure record**: G1/G2/G4 close requires `signed: <date> ev:jira{KEY-nn}` in the governing artifact (spec header for G1/G4, PLAN header for G2) — invoked as `gate-9 --gate G<n>`, where the record is **required**. The sweep form takes no gate and is a consistency lint (a SIGNED claim without a record, or a record without the claim), because a sweep does not know what is closing | gate sweep + gate close | gate not closed |
| GATE-10 | **Divergence diff (git↔Jira)** at gate open: statuses/sign-offs compared against the expected mapping (FORMATS §10); each divergence must be classified (git wrong / Jira wrong / real gap) **in the record's Classification column** before gate close. An empty diff is a claim like any other and carries an `ev:` citation of the query that produced it. Requires MCP; offline → the record says so **and** `jira-queue.md` carries an open gate-10 item, or the deferral is recorded nowhere that will be chased | gate open | block gate close on unclassified divergences |
| GATE-11 | **Legacy-framework freeze** (repos with `migrated_from_gsd: true` in wow.config.json): any commit touching `.planning/` is rejected — additions, edits, renames **and deletions**; it is frozen history in every direction. Guards against operator-level `/gsd:*` commands (installed user-wide) writing into a migrated repo. Inert-by-config in greenfield repos | pre-commit | block commit |

**formats.json content spec (single machine home, dual consumers):** `ids` (run/task/unit/DEV/PARK/VF/DEF/CV regexes) · `paths` (every repo-relative location the engines read) · `commit_trailers` · `branch_patterns` · `status_vocab` + forbidden synonyms + status columns · `claim_labels` · `evidence` types (each occurrence is shape-checked) · `scan_targets` (the gated document set) · `codebase_frontmatter` schema incl. the `p0-record` escape hatch · `dep_frontmatter` schema (FORMATS §11) · **`plan_schema`** (units, ownership lists, coverage matrix, tasks w/ verify, column names) · **`report_row_schema`** · **`requirements_row_schema`** · `jira_mapping` (FORMATS §10 table, divergence-record columns, closing gates) · `non_vacuity` (invariant/proof markers, test-file naming) · `legacy_freeze` · `runs_layout` · `audit_triggers` (incl. how each is derived) · `install` (what a complete installation is) · `sweep` (which gates run in a sweep, and which only at P5).

**The no-inline rule is testable:** a literal regex, path or status word in `gates.py` or `status.mjs` that belongs to one of those keys is a defect. Two consumers with private copies of a format is how enforcement and status derivation drift apart, which is the failure this whole file exists to prevent.

**Recovery on any gate failure:** FORMATS §7. **Explicitly not gates (judgment — ORCH/PO):** premise-check quality, unit sizing, autonomy-contract scope, contract-gap review, classification decisions, claim-label quality. A gate that pretends to check judgment is theater.
